# Развёртывание на хостинге ymaster.ru — пошаговая инструкция

Серверная часть рассчитана на **shared-хостинг с PHP 8.1+ и MySQL/MariaDB** (типовой тариф ymaster.ru). Все действия выполнимы из панели хостинга и браузера; SSH не обязателен.

---

## Шаг 1. Подготовка хостинга

1. Войдите в панель управления хостингом.
2. **PHP**: выберите версию **8.1 или новее** для домена/поддомена.
   Проверьте, что включены расширения: `pdo_mysql`, `curl`, `json`, `mbstring`
   (в cPanel/панели обычно всё включено).
3. **Домен**: выделите под API домен или поддомен, например
   `api.вашдомен.ru`. Папка сайта: запомните её путь (дальше — `ДОКУМЕНТ_РУТ`).

## Шаг 2. Создание базы данных

1. Панель → **Базы данных MySQL** → создать:
   - Имя БД: например `user_weather`
   - Пользователь: `user_wapp`
   - Пароль: сгенерируйте стойкий, сохраните.
2. Запишите: хост (обычно `localhost`), имя БД, пользователя, пароль.

## Шаг 3. Подготовка файлов локально

1. Откройте `server/config.example.php`.
2. Сохраните копию как `config.php` и заполните:

```php
'db' => [
    'driver' => 'mysql',
    'host' => 'localhost',
    'name' => 'user_weather',
    'user' => 'user_wapp',
    'pass' => 'ВАШ_ПАРОЛЬ',
],
'app' => [
    'url' => 'https://api.вашдомен.ru',
    'pepper' => '<64 случайных символа — сгенерируйте один раз!>',
    'rate_limit' => 120,
    'force_https' => true,
    'admin_email' => 'admin@вашдомен.ru',
    'admin_password' => 'СТОЙКИЙ_ПАРОЛЬ_АДМИНА',
],
'cron' => ['secret' => '<случайная строка>'],
```

Сгенерировать pepper/секрет можно любым генератором случайных строк
(64+ символов, буквы-цифры). **Не меняйте pepper после развёртывания** —
он участвует в device_hash и JWT.

## Шаг 4. Загрузка файлов на хостинг

**Вариант А (рекомендуется): document root → `server/htdocs`**

Если панель позволяет менять корневую папку сайта:
1. Загрузите весь каталог `server/` в домашнюю директорию
   (например `/home/u123/weather/`).
2. Установите корневую папку сайта в `/home/u123/weather/htdocs`.

**Вариант Б: корень фиксирован (public_html/www)**

1. Загрузите содержимое `server/htdocs/` в `public_html/`
   (index.php, cron.php, admin/, .htaccess).
2. Каталоги `src/`, `cron/`, файлы `config.php`, `install.php` загрузите
   **на уровень выше** public_html (рядом с ней), сохранив имена.
3. Структура: `~/src`, `~/cron`, `~/config.php`, `~/public_html/index.php`.

> Вариант Б безопаснее: `config.php` и `src/` гарантированно недоступны из веба.
> Для Варианта А тоже всё закрыто: конфиг и код лежат вне `htdocs/`,
> а `.htaccess` в `src/` и `cron/` дополнительно запрещают доступ.

## Шаг 5. Установка схемы БД

**Вариант А — через phpMyAdmin:**
1. Откройте phpMyAdmin → выберите вашу БД → вкладка **Импорт**.
2. Загрузите файл `server/schema.mysql.sql` → Выполнить.
3. Создайте администратора (SQL):

```sql
INSERT INTO users (uuid, email, password_hash, role, created_at, updated_at)
VALUES (
  UUID(), 'admin@вашдомен.ru',
  -- хэш пароля: замените на результат password_hash('ВАШ_ПАРОЛЬ', PASSWORD_BCRYPT)
  '$2y$10$ЗАМЕНИТЕ_НА_ХЭШ_ПАРОЛЯ',
  'admin', UTC_TIMESTAMP(), UTC_TIMESTAMP()
);
```

Хэш пароля можно получить PHP-онлайн исполнителем или командой
`php -r "echo password_hash('ВАШ_ПАРОЛЬ', PASSWORD_BCRYPT);"`

**Вариант Б — через SSH (если доступен):**

```bash
cd ~/weather          # каталог с install.php
php install.php
```

Установщик создаст все таблицы, справочники и админа из config.php.

**Вариант В — web-установщик:** загрузите `install.php` временно в
document root, откройте `https://api.вашдомен.ru/install.php`, затем
**удалите файл** с сервера.

## Шаг 6. Настройка SSL (HTTPS)

1. Панель → **SSL-сертификаты** → выпустите бесплатный Let's Encrypt
   для домена, включите принудительный редирект HTTP → HTTPS.
2. Включён `force_https => true` в config.php — API сам отклоняет
   небезопасные запросы.
3. Проверка: `https://api.вашдомен.ru/api/v1/health` → JSON со `status: ok`.

## Шаг 7. Настройка cron

В панели хостинга → **Планировщик задач (cron)** добавьте:

| Задача | Период | Команда (CLI) | или URL (HTTP) |
|---|---|---|---|
| Агрегация | раз в час, например `5 * * * *` | `php /home/u123/weather/cron/aggregate.php` | `https://…/cron.php?job=aggregate&token=СЕКРЕТ` |
| Загрузка прогнозов | каждые 30 мин `*/30 * * * *` | `php /home/u123/weather/cron/fetch_forecasts.php` | `…cron.php?job=fetch&token=СЕКРЕТ` |
| Очистка | раз в сутки `30 3 * * *` | `php /home/u123/weather/cron/cleanup.php` | `…cron.php?job=cleanup&token=СЕКРЕТ` |

Путь к PHP указывайте версии 8.1+ (панель подскажет, например
`/opt/php81/bin/php`). `СЕКРЕТ` — значение `cron.secret` из config.php.

## Шаг 8. Проверка установки

```bash
# 1. Здоровье
curl https://api.вашдомен.ru/api/v1/health

# 2. Регистрация тестового пользователя
curl -X POST https://api.вашдомен.ru/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"test@local","password":"password-123456","device_name":"cli"}'
# → запомните api_key из ответа (показывается ОДИН раз)

# 3. Отправка наблюдения
curl -X POST https://api.вашдомен.ru/api/v1/observations \
  -H 'X-Api-Key: wa_...' -H 'Content-Type: application/json' \
  -d '{"uuid":"11111111-1111-1111-1111-111111111111","lat":55.75,"lon":37.62,
       "observed_at":"2026-09-12T10:00:00Z","temp_c":15.0,"wind_ms":3.0}'

# 4. Агрегация (или дождаться cron)
curl 'https://api.вашдомен.ru/cron.php?job=aggregate&token=СЕКРЕТ'

# 5. Выдача агрегатов
curl -H 'X-Api-Key: wa_...' 'https://api.вашдомен.ru/api/v1/aggregates?kind=cell_hour'

# 6. Прогноз
curl -H 'X-Api-Key: wa_...' \
  'https://api.вашдомен.ru/api/v1/forecast?lat=55.75&lon=37.62&profile=roofer&hours=12'
```

Админ-панель: `https://api.вашдомен.ru/admin/` — вход admin_email/admin_password.

## Шаг 9. Подключение приложения

В приложении: **Настройки синхронизации** (иконка на главном экране):
1. Адрес сервера: `https://api.вашдомен.ru`
2. Email + пароль → «Зарегистрироваться» — приложение получит и сохранит
   api_key (или вставьте api_key вручную).
3. «Синхронизировать сейчас» — уйдут накопленные наблюдения, придёт bias.

Проверка: в админке появились строки в «Последние синхронизации»,
в приложении в настройках — «Синхронизировано».

## Шаг 10. Ежедневный контроль

- `/api/v1/health` — мониторинг (можно UptimeRobot на 5 мин).
- Админка → Сводка: наблюдения 24 ч, агрегаты 24 ч, bias источников.
- При росте нагрузки: увеличить `rate_limit`, включить предзагрузку fetch-задачей.

---

## Обновление сервера

1. Загрузите изменённые файлы поверх старых (кроме `config.php`).
2. Схема идемпотентна: повторный запуск `php install.php` ничего не сломает
   (создаёт только недостающие таблицы).
3. Проверьте `/api/v1/health`.

## Откат

Бэкап БД делается в phpMyAdmin (Экспорт). Файлы — простым копированием
назад. Приложение при недоступности сервера работает локально — откат
не влияет на пользователей.
