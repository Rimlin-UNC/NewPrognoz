# Безопасность и приватность — Weather Pro 2.0

## Модель угроз и защита

| Угроза | Защита |
|---|---|
| Перехват трафика | HTTPS обязателен (`force_https`), HSTS на уровне хостинга, `.htaccess` заголовки |
| Подбор API-ключей | Ключ 48 случайных байт; в БД только SHA-256 хэш; перебор невозможен по ответу (единый 401) |
| Брутфорс паролей | bcrypt (`password_hash`), rate limit на login, журнал неудачных попыток (audit_log) |
| DoS / абьюс API | Rate limiting 120 req/мин на ключ (таблица rate_limits), лимит батча 200, лимит выдачи 500 |
| SQL-инъекции | Только prepared statements (PDO) во всех запросах |
| XSS в админке | `htmlspecialchars` на выводе + CSP-заголовки хостинга; API отдаёт JSON с `X-Content-Type-Options: nosniff` |
| CSRF в админке | Сессионный CSRF-токен на все POST-формы, `session_regenerate_id` при входе |
| Утечка конфига | `config.php` вне document root (вариант Б) / вне htdocs (вариант А); `.htaccess` deny в `src/` и `cron/` |
| Манипуляция данными агрегатов | Многослойная валидация наблюдений (диапазоны, частота, MAD-выбросы), качество помечается, мусор не попадает в агрегаты |
| Подделка cron | `cron.php` требует секретный токен (hash_equals), CLI-запуск недоступен из веба |
| JWT-атаки | HS256 с pepper (не хранится у клиента), проверка alg, exp; короткий TTL 1 ч |
| Деанонимизация наблюдений | observations содержат только `device_hash = HMAC-SHA256(pepper, device_uuid)` — обратное отображение без pepper невозможно; в агрегатах персональных данных нет вообще |

## Приватность (GDPR-совместимый минимум)

- **Собираем:** email (логин), хэш пароля, метаданные устройства
  (имя/платформа/версия), обезличенные наблюдения (координаты + величины + время).
- **Не собираем:** имя, телефон, контакты, точную историю перемещений
  (наблюдения обезличены и агрегируются в ячейки ~11 км).
- **IP-адреса** хранятся только как HMAC-хэш (audit/sync_log) для расследования абьюза.
- **Право на удаление:** удаление аккаунта = `deleted_at` в users/devices;
  наблюдения уже обезличены и не связаны с аккаунтом.
- **Экспорт данных пользователя** возможен по запросу (users/devices/sync_log по email).
- **Третьи стороны:** прогноз приходит с api.open-meteo.com (без ключей,
  без идентификаторов пользователя; см. их политику).

## Чек-лист перед продакшеном

- [ ] `pepper` и `cron.secret` — 64+ случайных символов, не из примера
- [ ] `force_https = true`, SSL-сертификат активен
- [ ] Пароль админа — стойкий, `admin_password` удалён из config.php после установки (или файл config защищён вне docroot)
- [ ] `install.php` удалён из document root (если копировали)
- [ ] Ошибки PHP не показываются (display_errors=0 — уже в коде)
- [ ] Бэкапы БД включены в панели хостинга
- [ ] Мониторинг `/api/v1/health` (UptimeRobot и т.п.)
- [ ] Регулярно проверять админку → Журнал аудита

## Известные ограничения (по-честному)

- Shared-хостинг не даёт защиты от компрометации самого хостинга — для
  чувствительных сценариев используйте VPS (этап 3.0).
- Rate limit на таблице БД — при огромном RPS стоит перейти на Redis (3.0).
- JWT отзывается только истечением (TTL 1 ч); критичные операции — по API-ключу,
  который можно сменить созданием нового устройства.
