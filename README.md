# Метео-Аналитик 2.0

Метеорологическая аналитическая платформа с самообучением и дизайном уровня Apple (Glassmorphism). Приложение собирает прогнозы **шести погодных провайдеров**, ежедневно сверяет их с фактическим архивом и строит **ансамблевый прогноз**, взвешенный по исторической точности каждого источника.

> Реальные данные — открытый API [Open-Meteo](https://open-meteo.com) **без ключей**. Пять остальных источников — детерминированные симуляции (заглушки) с собственными погрешностями, чтобы алгоритм рейтингования работал в полную силу. Архитектура позволяет заменить заглушки на реальные API, не меняя остальную систему.

| Возможность | Реализация |

| 🌡 Ансамблевый прогноз | Взвешенное среднее 6 источников, вес = рейтинг/100 |
| 🏆 Рейтинг провайдеров 0–100% | Ежедневная сверка с архивом Open-Meteo History в **15:00 МСК** |
| 📉 График точности за 7 дней | Кастомный Canvas (без MPAndroidChart — экономия ~2 МБ) |

| 🧪 20+ метеопараметров | Bottom Sheet «Подробнее»: давление, видимость, УФ, точка росы, CAPE, влажность почвы и др. |
| 🍎 Apple Glassmorphism | Градиент тёмно-синий → фиолетовый, стеклянные карточки, анимации каскадом |
| 📦 Лёгкий APK | R8 + shrinkResources, Coil вместо Glide, ~11 МБ |

## Как работает самообучение

```
                ┌──────────────────────────────────────────────────┐
                │                15:00 МСК (ежедневно)             │
                └──────────────────────────────────────────────────┘
                   │                                   ▲
                   ▼                                   │ снапшоты прогнозов
   прогнозы, сделанные 24 часа назад ──────► СВЕРКА ◄── на завтрашние 15:00
   (таблица forecast_snapshots)                 │
                                               ▼
   Эталонная «истина»: Open-Meteo History ──► Score = 100 − (|ΔT|·8 + |ΔW|·4
   (среднее фактических часов 14:00–15:00)            + (осадки не совпали? 25 : 0))
                                               │
                                               ▼
   Рейтинг = взвешенное среднее скоров за 7 дней (0.30, 0.20, 0.15, 0.12, 0.10, 0.08, 0.05)
                                               │
                                               ▼
   Ансамбль: T_итог = Σ(T_i · rating_i/100) / Σ(rating_i/100)
```

**Жизненный цикл:**

1. **Первый запуск** — bootstrap: синтезируется история проверок за 7 дней (факт + детерминированная погрешность провайдера), чтобы рейтинги и график жили сразу. Показывается changelog.
2. **Каждый день в 15:00 МСК** (WorkManager, `VerificationWorker`): прогнозы, зафиксированные снапшотом ровно за 24 часа, сравниваются с фактом архива по температуре, ветру и осадкам.
3. **Рейтинг** каждого провайдера обновляется экспоненциальным сглаживанием за 7 дней — одна аномалия не обрушивает доверие.
4. **Все последующие прогнозы** строятся как взвешенное среднее с весами рейтингов.

## Источники данных

| # | Провайдер | Тип | Погрешность (симуляция) |
|---|---|---|---|
| 1 | **Open-Meteo** | реальный API, без ключа | — (эталон факта) |
| 2 | WeatherAPI | заглушка | ±1.5 °C, ±2 м/с |
| 3 | Visual Crossing | заглушка | смещение −0.4 °C, ±2.5 °C, ±3 м/с, добавка осадков |
| 4 | Tomorrow.io | заглушка | ±1.0 °C (+0.3 смещение), ±3.5 м/с, пропуск осадков |
| 5 | AccuWeather | заглушка | бинарный шум по осадкам (25%), ±0.8 °C, ±1.2 м/с |
| 6 | Custom | заглушка | усреднение Open-Meteo + WeatherAPI, микрошум |

Все заглушки **детерминированы** (seed = hash(провайдер, время)) — сверка «прогноза 24-часовой давности» воспроизводима. Для перехода на реальные API достаточно заменить реализации в `ProviderFactory` — интерфейс `WeatherProvider` останется прежним.

## Архитектура

- **Kotlin + Jetpack Compose** (Material 3) — реактивный UI
- **Room** — `providers` (рейтинги), `daily_checks` (сверки), `forecast_snapshots` (снапшоты на завтра)
- **WorkManager** — сверка ежедневно в 15:00 МСК + догоняющий разовый запуск
- **Retrofit + Moshi (codegen)** — запросы к Open-Meteo (прогноз + 5-летний архив)
- **Coroutines + Flow** — асинхронность, реактивные рейтинги из БД
- **Ручной DI** (`ServiceLocator`) — без Hilt, минимальный вес APK

## Формулы

**Суточный скор** (`ScoreCalculator`):

```
Score = 100 − ( |T_prog − T_fact| × 8
              + |Wind_prog − Wind_fact| × 4
              + (Rain_mismatch ? 25 : 0) )        ∈ [0..100]
```
`Rain_mismatch` — прогноз обещал осадки (>0.2 мм), а факта не было, или наоборот.

**Рейтинг** (`RatingCalculator`) — веса 7 дней от свежего к старому: `0.30, 0.20, 0.15, 0.12, 0.10, 0.08, 0.05` (при меньшем числе проверок веса перенормируются).

**Ансамбль** (`EnsembleCalculator`): `X_итог = Σ(X_i × rating_i/100) / Σ(rating_i/100)`.

**Достоверность** (`ConfidenceCalculator`): `Confidence = avgRating × 0.92^(часы_вперёд/24)`.

## Сборка APK

Полная инструкция — в [BUILD.md](BUILD.md). Кратко:

```bash
./gradlew clean
./gradlew assembleRelease
# APK: app/build/outputs/apk/release/app-release.apk (~11 МБ)
```

Требуется JDK 17 и Android SDK 34. Также можно собрать через GitHub Actions (workflow уже настроен, артефакт `MeteoAnalyst-release-apk`).

## Тесты

```bash
./gradlew testDebugUnitTest
```

Покрыты формулы скора, рейтинга, ансамбля и достоверности (`app/src/test/`).
